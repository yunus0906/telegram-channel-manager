## 1. 这个项目是做什么的

**Telegram Channel Manager** 是一个本地部署的 Telegram 频道管理与内容同步平台。它帮你：

- 发现并管理你（授权账号）能够访问的 Telegram 频道和超级群；
- 把频道里的消息**同步并保存到本地数据库**（默认 SQLite，也支持 MySQL 8.0+），形成一份可离线浏览、可导出的档案；
- 通过中文 Web 界面完成浏览、搜索、导出（JSON / JSONL / ZIP 媒体包）等操作；
- 即使关闭网页，后台任务也会继续运行。

简单理解：它就像一个**只属于你自己的、跑在本机上的 Telegram 频道备份和查看器**。

**它不能做什么**：它只能访问你的账号本身就有权限看的频道，不会帮你"突破权限"去看本来无权访问的内容。

## 2. 开始前需要准备什么

| 项目                                 | 是否必需 | 说明                             |
| ---------------------------------- | ---- | ------------------------------ |
| Python 3.11 或 3.12                 | 必需   | 本项目在 3.12.4 下开发测试              |
| Node.js 20.19+ / 22.12+            | 必需   | 运行前端界面                         |
| Telegram `TG_API_ID`、`TG_API_HASH` | 建议   | 用于登录 Telegram；**没有也能浏览已同步的内容** |
| 一个能访问目标频道的 Telegram 账号             | 建议   | 用来真正同步新内容                      |
| MySQL 8.0+（可选）                   | 可选   | 想用 MySQL 代替 SQLite 存储时才需要        |

> 小提示：如果只是想**先跑起来看看界面**，Python + Node 就够；Telegram 凭证和 MySQL 都可以稍后再补。默认用 SQLite，什么都不用额外装。

## 3. 首次配置

### 3.1 复制环境变量模板

进入 `backend` 目录，把 `.env.example` 复制成 `.env`：

```powershell
cd backend
Copy-Item .env.example .env
```

`.env` 文件里会包含这些配置项：

| 配置项                   | 作用               | 是否必填                |
| --------------------- | ---------------- | ------------------- |
| `TG_API_ID`           | Telegram 应用 ID   | 稍后可填                |
| `TG_API_HASH`         | Telegram 应用 Hash | 稍后可填                |
| `TG_PROXY_URL`        | Telegram 代理地址     | 直连超时时填写             |
| `ADMIN_PASSWORD_HASH` | 管理员密码的哈希         | **必填**              |
| `SESSION_SECRET`      | 会话密钥             | **必填**              |
| `DB_TYPE`             | 数据库类型（sqlite/mysql）| 默认 `sqlite`         |
| `DATABASE_URL`        | 数据库地址            | 留空用默认               |
| `MYSQL_HOST` 等        | MySQL 连接信息        | 用 MySQL 时必填          |
| `DATA_ROOT`           | 数据存放目录           | 默认 `./data`         |
| `HOST` / `PORT`       | 后端监听地址/端口        | 默认 `127.0.0.1:8000` |

### 3.2 安装依赖

推荐用 `uv`（速度快、可复现）：

```powershell
cd backend
uv sync --frozen --extra test --python 3.12
```

如果你没有安装 `uv`，可以用传统的虚拟环境方式：

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 3.3 生成管理员密码哈希和会话密钥

这是**最关键的一步**。后端启动时如果缺少 `ADMIN_PASSWORD_HASH` 和 `SESSION_SECRET` 会直接拒绝启动。

**第一步：生成管理员密码哈希**

```powershell
& .\.venv\Scripts\python.exe scripts\hash_admin_password.py
```

运行后会提示你输入密码，然后输出一串哈希值。把这串哈希**填到 `.env` 的 `ADMIN_PASSWORD_HASH` 后面**。

> ⚠️ 注意：`.env` 里填的是**哈希值**，不是密码明文。永远不要把密码明文写进 `.env`。

**第二步：生成会话密钥**

```powershell
& .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

输出一串随机字符串，填到 `SESSION_SECRET` 后面。

**第三步（可选）：填入 Telegram 凭证**

如果你已经申请了 Telegram 应用，把 `TG_API_ID` 和 `TG_API_HASH` 也填进去。没有的话先留空，后面随时可以补。

### 3.4 （可选）配置 Telegram 代理

如果你所在的网络直连 Telegram 超时或连不上，可以在 `.env` 里设置 `TG_PROXY_URL` 走代理：

```dotenv
TG_PROXY_URL=http://127.0.0.1:10809
```

也支持 `socks4://` 和 `socks5://` 协议。填写后需要**重新安装后端依赖并重启后端**才生效。代理要允许连接 Telegram 的 TCP 端口；留空表示直连。

### 3.5 （可选）选择数据库

项目默认使用 **SQLite**（`DB_TYPE=sqlite`），数据库文件位于 `DATA_ROOT/manager.sqlite3`，零配置、开箱即用，绝大多数情况用这个就够了。

如果你想用 **MySQL 8.0+** 存储（适合数据量大、需要独立数据库服务的场景），步骤如下：

1. 在 MySQL 里创建一个使用 `utf8mb4` 字符集的空数据库，并给应用账号授予该库的建表、改表、索引和读写权限。
2. 在 `backend/.env` 中设置：

```dotenv
DB_TYPE=mysql
DATABASE_URL=
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=manager
MYSQL_PASSWORD=填写数据库密码
MYSQL_DATABASE=manager
```

> 注意：MySQL 模式下 `MYSQL_HOST`、`MYSQL_USER`、`MYSQL_PASSWORD` 和 `MYSQL_DATABASE` **必须填写**，`DATABASE_URL` 必须**留空**。连接失败时后端会直接报错启动失败，不会自动退回 SQLite。切换数据库不会自动迁移数据，MySQL 会从空库开始。

## 4. 启动项目

需要**两个终端**，分别启动后端和前端。

### 4.1 启动后端（终端一）

```powershell
.\scripts\start-backend.ps1
```

或者手动运行：

```powershell
cd backend
& .\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

看到日志输出、没有报错，即表示后端启动成功。首次启动会自动执行数据库迁移（Alembic `upgrade head`）。

### 4.2 启动前端（终端二）

```powershell
.\scripts\start-frontend.ps1
```

或者手动运行：

```powershell
cd frontend
npm ci
npm run dev
```

### 4.3 打开界面

浏览器访问 **http://127.0.0.1:5173**。

- 前端界面地址：`http://127.0.0.1:5173`
- 后端 API 地址：`http://127.0.0.1:8000/api/v1`
- 健康检查：`http://127.0.0.1:8000/api/v1/health`

## 5. 登录与授权

1. 打开 `http://127.0.0.1:5173`，用你**在 3.3 步骤设置的密码**登录（注意填的是密码本身，不是哈希）。
2. 登录后进入 **"系统设置"** 页面，发起 **Telegram 登录**。
3. 手机号**必须带国家码**，写成 `+8613800000000`。只写 `13800000000` 会被 Telegram 当成其他国家号码，直接报「请求验证码失败」。
4. 按照提示输入 Telegram 发来的**验证码**；如果账号开了两步验证，还需要输入二次密码。
5. 登录成功后，该账号会出现在设置页的账号列表里，标记为「使用中」。

### 5.1 多账号（同时管理多个 Telegram 账号）

- **每个手机号各自一份 session**：登录 `+8613800000000` 会写到 `backend/data/accounts/8613800000000/telegram.session`，账号之间互不影响，不会再出现"换个号登录就报错"。
- 设置页的账号列表里点 **"切换"** 即可换用另一个账号，不需要重新收验证码。同一时刻只有一个账号是活动状态（对应一个后端进程里的一个客户端）。
- 之前已经登录过的账号保留在 `backend/data/telegram.session`，在列表里显示为 **"旧 session"**，可以直接切换回去，也可以重新登录一个新号。
- 点 **"移除"** 只会删除本机保存的 session 文件。**Telegram 端的登录态不会自动退出**，如果确实要下线，请到 Telegram 的「设置 → 已登录设备」里手动移除。
- 注意：频道列表是全局共用的。某个频道只有在**当前活动账号有权访问**时才能同步，否则该频道的「最近错误」会提示无法访问。

> 整个流程中，验证码、密码、API Hash、消息正文都不会被记录到日志里，可以放心。

## 6. 日常使用流程

### 6.1 发现频道

在界面里点击 **"发现频道"**，系统会读取你授权账号**实际可访问**的频道和超级群列表。

- 私有频道只显示标题、Chat ID 和授权状态，不会构造公开链接（保护隐私）。
- 把频道加入管理列表，**不会自动开始同步**，需要手动启动（见下一步）。

### 6.2 历史同步

对已添加的频道启动**历史同步**任务。系统会按 Telegram 消息 ID 从新到旧分批扫描，把消息、事件、任务游标在同一数据库事务内提交。

- 消息按"频道 + 消息 ID"去重，内容没变化就不会产生重复的编辑事件。
- 大任务会返回一个**任务 ID**，你可以在界面里看到进度、状态和错误信息。
- 运行中的同步和校准可以在批次之间暂停或取消。

### 6.3 启用监听（实时更新）

对频道**启用监听**后，新的消息和编辑会实时进入本地档案。

> 注意：监听只处理"已管理 **且** 已启用监听"的频道。

### 6.4 导出内容

支持多种导出格式：

| 格式            | 说明                    |
| ------------- | --------------------- |
| JSON          | 结构化快照                 |
| JSONL         | 每行一个事件，带稳定 `event_id` |
| JSON + 媒体 ZIP | 快照 + 已下载的媒体文件         |
| 仅媒体 ZIP       | 单个频道或全部频道的媒体打包        |

导出文件会自动落在 `DATA_ROOT` 目录下，路径由程序生成，保证安全。

## 7. 数据备份与恢复

备份前**先停止后端**。

### 7.1 备份（SQLite 模式）

复制整个 `backend/data` 目录（或你自定义的 `DATA_ROOT`），里面包含 SQLite 数据库、session 文件、媒体和导出文件。

### 7.2 备份（MySQL 模式）

使用 MySQL 时，需要**分别**备份两样东西：

1. **MySQL 数据库**：用你熟悉的 MySQL 备份工具（如 `mysqldump`）导出数据库。
2. **`DATA_ROOT` 目录**：里面包含 session、媒体和导出文件。

### 7.3 恢复

1. **停止后端**。
2. 恢复数据库（SQLite 放回文件，MySQL 导入备份），并把 session/媒体/导出文件放回 `DATA_ROOT`。
3. 检查文件权限（Windows 上系统会尝试用 `icacls` 限制 session 文件为当前用户可访问）。
4. 重新启动后端，Alembic 会自动升级旧数据库。

> ⚠️ 备份和 session 文件**一定不要提交到 Git**。

## 8. 常见问题排查

### 8.1 后端启动失败

- 检查 `.env` 里 `ADMIN_PASSWORD_HASH` 和 `SESSION_SECRET` 是否都已填写（这两个是必填项，缺失会导致拒绝启动）。

### 8.2 端口被占用

- 默认端口是 `8000`（后端）和 `5173`（前端）。如果被占用，可在 `.env` 里改 `PORT`，或在启动命令里加 `--port` 参数。

### 8.3 Telegram 登录失败 / 连接超时

现在报错会直接说明原因：响应里的 `message` 是可执行的排查提示，末尾括号里是 Telegram 返回的异常类名。

- `手机号格式不正确，请使用带国家码的国际格式，例如 +8613800000000（PhoneNumberInvalidError）`
  → 手机号必须带国家码，写成 `+8613800000000`；写成 `13800000000` 会被当成其他国家号码。
- `Telegram 要求等待 42 秒后再试（FloodWaitError）`
  → 请求验证码过于频繁，等够时间再试，不要连续点击。
- `无法连接 Telegram，请检查网络与 TG_PROXY_URL 代理设置（ConnectionError / TimeoutError）`
  → 在 `.env` 里设置 `TG_PROXY_URL`（见 3.4 节）后重启后端。
- `本地 Telegram session 已失效…（AuthKeyUnregisteredError / SessionRevokedError）`
  → 停止后端，删除 `backend/data/telegram.session` 后重新登录，并在 Telegram「已登录设备」里移除旧会话。
- `该 API 凭证已被 Telegram 判定为公开…（ApiIdPublishedFloodError）`
  → 这对 `TG_API_ID` / `TG_API_HASH` 是从教程或仓库抄来的，请到 https://my.telegram.org 申请自己的。

排查入口：

- 出错弹窗和「系统设置」页顶部的「最近错误」都会显示异常类名，可直接搜索定位。
- 完整异常堆栈写在 `backend/data/logs/backend.log`（随 `DATA_ROOT` 变化，设置页会显示实际路径），后端控制台同步输出。

> 提示：每个手机号各自一份 session（见 5.1 节），所以对一个新的手机号点「发送验证码」不会影响已登录的账号；登录完成后用账号列表里的「切换」来换号。

### 8.4 MySQL 连接失败

- 确认 `.env` 里 `DB_TYPE=mysql`、`MYSQL_*` 四项都已填写、`DATABASE_URL` 已留空。
- 确认数据库已预先创建，且账号有建表、改表、索引和读写权限。
- 注意：连接失败时后端会直接启动失败，**不会自动退回 SQLite**。

### 8.5 想从其他设备访问

- 默认只监听 `127.0.0.1`，仅本机可访问，这是安全的默认值。
- 如需经 HTTPS 反向代理供其他设备访问，必须设置：
  - `CORS_ORIGINS` 为具体来源；
  - `COOKIE_SECURE=true`；
  - 把后端放在可信代理之后。
- ⚠️ **不要**把管理端口直接暴露到公网。

### 8.6 想确认代码是否正常

运行测试套件：

```powershell
cd backend
& .\.venv\Scripts\python.exe -m pytest -q
& .\.venv\Scripts\python.exe -m compileall -q app
cd ..\frontend
npm run typecheck
npm run build
npm run lint
npm test
```

## 附：重要注意事项汇总

- **单进程架构**：不要启动多个 Uvicorn worker，否则会产生多个 Telegram 客户端和任务执行器，导致冲突。
- **凭证安全**：验证码、密码、API Hash、session 文件、消息正文都不会写进日志。
- **数据保留**：项目不会因为 Telegram 端删除了消息就自动删除本地档案；历史校准只负责补漏和更新编辑内容。
- **数据库选择**：默认 SQLite 适合小规模使用；数据量大或需要独立数据库服务时可切 MySQL，但切换不会自动迁移已有数据。
- **规模定位**：项目仍采用单后端进程，不支持多个实例共享同一 Telegram session 或任务执行器。
